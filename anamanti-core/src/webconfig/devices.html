The displays connected to this Core, the local music processes it supervises, and your radio stations. Every action here applies immediately.

Displays

Displays holding a live notify channel open to this Core, with the name each one announced. Names and ids are set on the device's Settings screen (the id comes from its Wi-Fi MAC). Refreshes every 10 s.

Music player on each display

What each display shows while Spotify or the radio plays. Automatic: full screen on the display the music was asked for from, the small bar on the others. While music plays, each display can also switch itself with its expand / minimize button or by voice ("make the music full screen", "use the small music player"); that lasts until the music stops or something new is played.

Send a test notification

Appears on the idle screen of every connected display without anyone speaking. Visual only: nothing is spoken.

Dropped if no display is connected.

Music

Local multiroom audio: the Core starts and stops snapserver, which runs the Spotify (librespot) and radio (mpv) players itself; the Core only sends them commands and never handles the audio. Spotify is linked under Integrations → Spotify.

Music routing is disabled.
Set "music": {"enabled": true} in anamanti.json and restart the Core to manage the music processes here.

Radio stations

Live stations played on the same speakers as Spotify (mpv → the snapserver Web stream). Starting one pauses Spotify; starting Spotify stops the radio. Say "play Dave Rocks", "next station" or "stop the radio". The display's now-playing screen shows the logo, station and current song. The ID is the station's call sign; aliases are extra names to say. Look up sends the stream URL / name you typed to the public Radio Browser directory to find the name and logo.

Music routing (or the mpv web player) is off, so stations can be edited but not played. Enable "music" in anamanti.json.
